Three distinct checks

  1. Lean build: the formal statements and proof terms elaborate under the pinned toolchain.
  2. Axiom audit: every compiled declaration exported by the imported implementation modules is checked against the three standard logical axioms listed above.
  3. Wiki integrity: manuscript labels, editorial pointers, source line anchors, local links, and deterministic generated files are checked by the site builder.

The site builder does not rerun the Lean build or the axiom audit. It verifies that its source files match the selected audit’s recorded hashes, and that referenced declarations occur in both source and compiled inventory.

Rebuild or check this wiki

From the repository root, using Python 3.10 or newer:

python3 tools/docs-site/build.py
python3 tools/docs-site/build.py --check

Open docs/index.html directly in a browser, or serve the directory with any static web server. Search, mathematics, navigation, and source pages use bundled assets and relative URLs; no network request is needed.

Reproduce the formal audit

The repository’s verification runner and pinned Lean project remain the authoritative workflow. The commands below run from the repository root:

cd formalization
lake build All
python3 scripts/check_checkpoint.py
python3 scripts/audit.py --jobs 3

The checkpoint command checks saved evidence without running Lean. The audit command performs a fresh build and complete compiled-declaration audit. See the complete verification instructions for output directories and scope.

Design and bundled software

The reading-route, named-result, and exact-source organization is inspired by the Fermat’s Last Theorem proof wiki and its HTML project. This site uses its own layout, styles, and generator.

Mathematics is rendered locally by KaTeX using native MathML. KaTeX is distributed under the MIT license; no third-party styles or fonts are loaded.
