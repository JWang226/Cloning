## What the pinned source establishes

Lean's heartbeat counter measures small allocations on the current thread. Counter reset is a separate operation. The runtime increments the counter in the small-allocation path, including both allocator configurations. [IO heartbeat API](https://github.com/leanprover/lean4/blob/00659f8e6071d7e46131ed643bf8003b99b044e9/src/Init/%53ystem/IO.lean#L586-L598), [runtime allocation counter](https://github.com/leanprover/lean4/blob/00659f8e6071d7e46131ed643bf8003b99b044e9/src/runtime/alloc.cpp#L384-L387), [non-small-allocator object path](https://github.com/leanprover/lean4/blob/00659f8e6071d7e46131ed643bf8003b99b044e9/src/include/lean/lean.h#L347-L355).

Core timeout checks compare the current counter against the context's starting counter. Instance search establishes its own starting context and checks its synthesis budget through the same mechanism. Both option families scale user-facing values by 1,000 internally. [Core heartbeat check](https://github.com/leanprover/lean4/blob/00659f8e6071d7e46131ed643bf8003b99b044e9/src/Lean/CoreM.lean#L169-L174), [timeout comparison](https://github.com/leanprover/lean4/blob/00659f8e6071d7e46131ed643bf8003b99b044e9/src/Lean/CoreM.lean#L465-L491), [typeclass budget and check](https://github.com/leanprover/lean4/blob/00659f8e6071d7e46131ed643bf8003b99b044e9/src/Lean/Meta/SynthInstance.lean#L19-L37), [synthesis check](https://github.com/leanprover/lean4/blob/00659f8e6071d7e46131ed643bf8003b99b044e9/src/Lean/Meta/SynthInstance.lean#L190-L196), [synthesis starting scope](https://github.com/leanprover/lean4/blob/00659f8e6071d7e46131ed643bf8003b99b044e9/src/Lean/Meta/SynthInstance.lean#L632-L646).

With `trace.profiler=true`, trace wrappers run extra trace-state bookkeeping, timing/result packaging and message/tree construction instead of directly invoking the wrapped action. They do not save and restore the allocation heartbeat counter around that added work. Even nodes below the recording threshold take the enabled wrapper path. **Inference from these implementations:** profiler small allocations on the active elaboration/search thread can consume its checked heartbeat budget. This establishes a mechanism, not the exact number or origin of allocations that triggered these two errors. [Trace wrappers](https://github.com/leanprover/lean4/blob/00659f8e6071d7e46131ed643bf8003b99b044e9/src/Lean/Util/Trace.lean#L274-L300), [before-action trace wrapper](https://github.com/leanprover/lean4/blob/00659f8e6071d7e46131ed643bf8003b99b044e9/src/Lean/Util/Trace.lean#L390-L419), [trace-tree construction](https://github.com/leanprover/lean4/blob/00659f8e6071d7e46131ed643bf8003b99b044e9/src/Lean/Util/Trace.lean#L145-L172).

The Firefox exporter is reached only after the frontend's `hasErrors` return. The pp option controls message formatting inside that exporter. Therefore **post-elaboration pp=true export cannot explain these logged elaboration failures**; export is not executed on this failed path, and the missing Firefox JSON is expected. In-process tracing and its allocations are distinct from final pretty-printing/export. [Frontend error return and export order](https://github.com/leanprover/lean4/blob/00659f8e6071d7e46131ed643bf8003b99b044e9/src/Lean/Elab/Frontend.lean#L190-L215), [export formatting](https://github.com/leanprover/lean4/blob/00659f8e6071d7e46131ed643bf8003b99b044e9/src/Lean/Util/Profiler.lean#L198-L213).
